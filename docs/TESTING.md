# Empire of Minds — Test profiles (T1) and validation policy (T2)

The project has a large server (pytest) and Godot headless regression suite. **Profiles** run a subset during day-to-day work. **`full`** is unchanged and still runs every test when explicitly requested; it is **not** the default for small focused slices.

No profile deletes or weakens tests. Failures are not suppressed.

## Validation policy (T2) — default for agents and implementation prompts

**During implementation:** run **only** the profile that matches the slice you are changing.

```text
.\scripts\run-godot-tests.ps1 slice c14c
.\scripts\run-godot-tests.ps1 slice c14d
.\scripts\run-godot-tests.ps1 slice c14d-dev
.\scripts\run-server-tests.ps1 slice c14b
```

**Final report on a small/local slice:** run the **slice** profile again; add **smoke** only when shared boot/session/helper code was touched. **Do not** run **cloud**, **presentation**, or **full** unless the user explicitly asks or you are doing a release/deploy checkpoint (see below).

**Future Composer/Cursor prompts** should state the intended validation level, for example:

```text
Validation:
- During implementation, run only the slice profile.
- For final report, run slice and optionally smoke.
- Do not run full/cloud/presentation unless explicitly requested.
```

### Agent final-report checklist

Report:

1. **Focused tests run** (commands + pass/fail).
2. **Broader tests intentionally skipped** (e.g. cloud, full, presentation).
3. **Why** broader tests were skipped (slice-local change; user did not request full regression).
4. Whether **full** validation is **recommended** before commit/deploy for this change.

### When to use each profile

| Profile | Use when |
|--------|----------|
| **slice \<id\>** | **Default** while implementing and reporting on a focused slice (e.g. **c14c**, **c14b**, **c14d**) |
| **smoke** | Small change touches **shared** setup/boot/session/helper code; quick sanity without full regression |
| **cloud** | Broad cloud client/server change; shared **CloudSession** / **CloudClient** behavior across flows; cloud deploy prep; **user explicitly requests** broader cloud validation |
| **presentation** | Broad map/presentation/rendering changes; UI rendering outside a narrow menu slice; **user explicitly requests** presentation validation |
| **full** | **User explicitly requests**; final commit/deploy for a **large** slice; after a **large refactor**; suspected **cross-cutting** regression; release-like checkpoint |

### Slice-specific defaults (small changes)

**Godot front door / menu / labels / credential-store UX (e.g. C14c):**

- Normally: `.\scripts\run-godot-tests.ps1 slice c14c
.\scripts\run-godot-tests.ps1 slice c14d
.\scripts\run-godot-tests.ps1 slice c14d-dev`
- If **BootIntent** or **main.gd** boot flow changed: also `.\scripts\run-godot-tests.ps1 smoke`
- **Do not** run **full**, **cloud**, or **presentation** unless explicitly requested.

**Small server endpoint/model slice (e.g. C14b, C14d-1):**

- Normally: `.\scripts\run-server-tests.ps1 slice <slice_id>` (e.g. **`c14d`** for staging faction/ready)
- If shared match/action plumbing changed: also `.\scripts\run-server-tests.ps1 smoke`
- **Do not** run **full** or broad Godot **cloud** unless explicitly requested or preparing deploy.

**Asset-generation tooling slice (e.g. C1):**

- Provider adapters, manifests, GLB validators and gates are Python under `tools/assetgen/`: `python -m pytest tools/assetgen/tests -q`. Since **A2.11** this also covers the rigged-humanoid ingestion owner (`test_rig_ingest.py`, `test_hand_fixture_ingest.py`): the `0` accepted / `2` classified asset-fixture FAIL / `1` infrastructure exit protocol, that the pipeline runs `--headless --import` itself before certifying, that a fingerless rig is a named `HAND_SKELETON_INCOMPLETE` rejection rather than a generic step failure, that a compiler PASS with a failed bind-sanity or grip gate still refuses to publish, that publishing happens only on a fully accepted chain and rejected artifacts stay in staging, and that reruns are idempotent. Since **A2.12** it also covers the publish boundary itself: only the certified fixture is publishable (never the compiler's staged evidence), publication is atomic via a temporary file beside the destination, an interrupted or failing publish leaves the previous accepted artifact byte-identical, and a rejection neither publishes nor deletes an earlier accepted version. Since **A2.13a** the ingestion fixtures assert the honest chain: `bind_sanity` and `grip_ground_truth` are one `assemble_and_measure` step, and `certification` is the chain's consequence rather than a step in it, so a compiler PASS that fails the assemble/measure gate is asserted at that stage name.
- Since **C2** it covers the live barriers (`test_provider_live_barriers.py`). Two rules keep those tests from being falsely green, and both are load-bearing: assertions are on **real call counters** (`double.create_calls == 1`) rather than on reported state, because a manifest claiming `CREATED` is a claim and a counter is evidence; and each test asserts the **exact refusal code**, because a "it refused somehow" assertion would keep passing if the barrier ordering regressed and a credential were read before authorization. Covered: no flags with and without a credential present (a configured key must change nothing), `--live` without the opt-in, the opt-in without `--live`, non-exact opt-in values (`0`/`false`/`yes`/`true`/`2`/empty), both barriers without a plan confirmation, a foreign digest, a digest gone stale because the input file changed, a plan whose own preflight refuses the input, a missing credential *after* all three barriers, adapter construction reading no credential at all, no credential in stdout/manifest/response snapshot/exception even when the provider echoes it back, no credential as any subcommand's option, a create timeout never resubmitting, an ambiguous create recorded as `UNKNOWN` rather than `FAILED`, a restart resuming the same paid task from the store alone, one plan digest refusing a second submission, the claim existing before the request so a crash leaves evidence, bounded polling, a corrupt download whose hash records what actually arrived, a missing bundle staying a classified failure, and neither a compiler FAIL nor a grip FAIL publishing while a full ACCEPTED chain publishes atomically. A sabotage check confirmed the suite is not vacuous: disabling the opt-in barrier and re-enabling create retries turned 10 tests red.
- Since **C2r** it also covers the capability boundary (`test_provider_capability_boundary.py`), one regression per audited finding, written the way the review *measured* each defect rather than the way the fix is structured. Covered: `auth-smoke --live` reaching neither a credential nor the network, both non-paid barriers required for a read-only probe, all three paid commands requiring all three barriers and acquiring the same ledger claim, a direct orchestrator or adapter call without a capability refusing before any credential access, a hand-built capability refused, a network-read capability unable to create, a capability refusing another provider/operation/endpoint, a paid capability refusing reuse, an `UNKNOWN` outcome refusing replay, concurrent submissions creating exactly once, an endpoint change invalidating the digest, an authenticated cross-origin redirect refused, environment proxies not consulted, every CLI command carrying a risk class, provider-controlled names never becoming paths (drive, UNC, `/tmp`, traversal, mixed separators, encoded traversal, symlinked output directory, colons and reserved device names), an adapter writing only where the orchestrator told it to, request `repr` and Basic tokens redacted, and no networking subprocess launched from provider code. **Sabotage results (12 injected defects, all detected):** removing the opt-in barrier turned 10 red; re-enabling create retries 4; removing the adapter capability check 5; removing the transport capability check 3; dropping the endpoint from the digest 1; making the claim non-exclusive 1; removing the `UNKNOWN` replay check 1; an adapter re-deriving its own filename 9; removing path validation 13; a leaky request `repr` 1; an eager `os.environ` credential read 2; and dropping derived secret forms 1.
- Always: `python scripts/scan-secrets.py` (changed + untracked files).
- If a Godot diagnostic scene changed: `.\scripts\run-godot-tests.ps1 slice c1`.
- **A1/A2 are not required** when the diff touches only `tools/`, `scripts/` and a new diagnostics scene: no gameplay, rig, grip or walking-preview code is reachable from them. Say so explicitly in the report rather than running them by reflex.
- **Real provider calls must never be part of a suite.** Since **C2** this is mechanical rather than conventional. `tools/assetgen/tests/conftest.py` is autouse and does two things for every test: it clears `MESHY_API_KEY`, `MESHY_API_BASE`, `UTHANA_API_KEY`, `UTHANA_API_BASE` and `EOM_ALLOW_PAID_PROVIDER_CALLS`, so a green suite can never depend on the developer's own credentials or on a spend opt-in left over from a real run; and it arms the `net_guard.py` socket tripwire, so `socket.connect`, `create_connection` and `getaddrinfo` all raise `NetworkForbidden` for any non-loopback target. That catches what transport injection cannot: a new adapter calling `urllib` directly, or a library doing its own fetch. **Tests use only synthetic secrets**, and masking does not depend on a value looking like a real key.

**Docs-only / decision checkpoint slice (e.g. C14d-0, C14d-final):**

- **No** runtime suites — the diff touches only `docs/`.
- If a docs-only task implies code changes, **stop and report** instead of writing code.
- **C14d-final (cloud-alpha external checkpoint):** documents the passed external two-player test, zip + `.bat` distribution, Smart App Control tester notes, and manual checklist in **`docs/VALIDATION_CHECKLIST.md`** / **`docs/CLOUD_ALPHA_RELEASE.md`**. Agents: final report must state **tests not run** (T2 docs-only).

### What not to do

- Do not run **cloud** or **full** “because the task mentioned cloud” when the diff is a narrow UI/credential/menu slice.
- Do not treat **full** as the default final step for every implementation report.
- Do not suppress failing tests or runner output to hide noise (see [Known noisy output](#known-noisy-output-not-hidden)).

## Known noisy output (not hidden)

Some Godot cloud negative tests use `::not-a-url::` so HTTP fails immediately; tests **pass** but Godot logs red `ERROR: Error parsing URL` lines. That is intentional test harness noise, not a profile failure.

Image-load `WARNING` lines (e.g. combat burst, territory stump) may appear in presentation tests; they are not suppressed.

`slice a2` prints a red `ERROR: uthana_a2_preview: equip failed: club_missing CLUB_MISSING` from `test_uthana_a2_preview_runtime.gd`. That is the deliberate broken-weapon negative case proving the preview fails closed with a named cause; the test passes. Judge the profile by the runner's exit code and the `All N headless tests passed` line, never by the presence of red lines. Do **not** pipe the runner through `2>&1` — the runner's `ErrorActionPreference = "Stop"` turns native stderr into a terminating error and aborts the profile mid-run, which looks exactly like a test failure.

Headless runs of tests that free nodes carrying duplicated `StandardMaterial3D` overrides (e.g. `test_world_units_view.gd`) may log engine-internal `ERROR: Parameter "material" is null.` lines from the dummy rendering server; the tests pass and the errors do not occur in real (non-headless) rendering.

## Extending profiles

Add new slice ids to `$Script:SliceTests` / `$Script:SupportedSlices` in the runner scripts. Prefer explicit file lists for **smoke** and **slice**; **cloud** / **presentation** on Godot filter the full list by path prefix so new files under those folders are picked up automatically when added to the full suite.

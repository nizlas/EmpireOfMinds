## Runtime flow

1. **Local run (default):** [main.gd](../game/main.gd) constructs **Scenario**, **HexLayout**, **SelectionState**, **GameState**, wires map layers, HUD panels, [SelectionController](../game/presentation/selection_controller.gd), [EndTurnController](../game/presentation/end_turn_controller.gd), [AITurnController](../game/presentation/ai_turn_controller.gd). It is **wiring-only** — not authoritative gameplay logic. **Cloud prototype (Slice C8, opt-in):** the same wiring is fed a **GameState** built from the server **snapshot v2** (skip local **ProductionDelivery** / movement refresh at init); input branches **`POST .../actions`** and **`GET .../legal-actions`** instead of **`try_apply`** for supported actions.
2. **Every gameplay change:** an action **dictionary** enters **[`GameState.try_apply`](../game/domain/game_state.gd)** (`RefCounted`).
3. **Validation + apply:** `try_apply` dispatches by `action_type` to modules under **`game/domain/actions/`** ([MoveUnit](../game/domain/actions/move_unit.gd), [AttackUnit](../game/domain/actions/attack_unit.gd), [FoundCity](../game/domain/actions/found_city.gd), [SetCityProduction](../game/domain/actions/set_city_production.gd), [EndTurn](../game/domain/actions/end_turn.gd), [CompleteProgress](../game/domain/actions/complete_progress.gd), [SetCurrentResearch](../game/domain/actions/set_current_research.gd), …). **`CombatRules`** ([combat_rules.gd](../game/domain/combat_rules.gd)) resolves **`attack_unit`** once; **`AttackUnit.apply_with_result`** applies that snapshot only.
4. **Domain transition pattern:** validated actions rebuild an immutable **[Scenario](../game/domain/scenario.gd)** snapshot (units, cities, **`HexMap`, id counters**, **`lightning_tree_hex`**). **[ActionLog](../game/domain/action_log.gd)** gains an accepted entry where applicable.
5. **Ticks on [`EndTurn`](../game/domain/actions/end_turn.gd)** (inside **`GameState.try_apply`**): [ProductionTick](../game/domain/production_tick.gd) appends **`production_progress`** entries; [FoodGrowthTick](../game/domain/food_growth_tick.gd) may append **`food_growth_progress`** / **`city_grew`**; [ScienceTick](../game/domain/science_tick.gd) may append Ancient-era accumulation lines **before** the **`end_turn`** record advances **`TurnState`**; **`end_turn`** is logged (the returned **`try_apply`** index targets this row); then [ProductionDelivery](../game/domain/production_delivery.gd) runs for the **new** actor (**`unit_produced`**). Canonical ordering: **[TURNS.md](TURNS.md)**, **[ACTIONS.md](ACTIONS.md)**.
6. **Presentation refresh:** controllers assign **`scenario` / `game_state`** handles into **`Node2D`** views (`queue_redraw`, HUD `refresh`). **[TurnViewSync](../game/presentation/turn_view_sync.gd)** is a small **`RefCounted`** helper (**not** a bus, registry, or pub/sub): **`refresh_map_views_and_hud_after_try_apply_turn_controllers`** centralizes terrain/map-layer redraws (`selection_view`, **`units_view`**, **`TerrainForegroundView`**, **`MapVisibilityView`** (**5.2.3** — parchment fog for **`current_player_id`** explored complement), nameplates, yield overlay, territory) plus turn label **`refresh`** and the HUD **`refresh`** calls invoked from **EndTurn** / **AI** paths after an accepted **`try_apply`**; **`sync_terrain_related_views`** handles the terrain-related map-layer/sync path delegated from **[SelectionController](../game/presentation/selection_controller.gd)** (including **`MapVisibilityView.game_state`** + **`queue_redraw`** when **`game_state`** is passed). Controllers still own accepted-action handling, **`DiscoveryPopup`** sequencing, and any view/HUD updates not covered by those helpers. **5.2.1:** **EndTurn** (and AI-accepted **`end_turn`**) clear **unit** + **city** + **planning** via **`EndTurnController.apply_hotseat_clear_after_accepted_end_turn`** before **`TurnViewSync`** (see **Turn control** below).

### Turn control / local hotseat prototype

**Phase 5.2.0** names the shipped local mode **local hotseat prototype** (single instance; human can play every seat in turn).

- **[`GameState.try_apply`](../game/domain/game_state.gd)** rejects actions when **`action["actor_id"] != turn_state.current_player_id()`** (**`not_current_player`**), before type-specific validation — same gate for humans and AI-chosen actions.
- **[`TurnState`](../game/domain/turn_state.gd)** holds **`players`**, **`current_index`**, **`turn_number`** only. There is **no** domain **`seat_kind`**, **human-player assignment**, or **remote/local** split.
- **Presentation** drives input for **whoever is current**; **[`TurnStatusPanel`](../game/presentation/turn_status_panel.gd)** shows hotseat copy **`Player N's turn`** (not “waiting for …”) and tints from **`UnitNameplateView.owner_nameplate_accent_color`**. **`local_player_id`** on that panel is **presentation-only**, reserved for **future remote-seat** UX; it does **not** gate **`try_apply`** today.
- **[`AITurnController`](../game/presentation/ai_turn_controller.gd)** is **manual** (**`KEY_A`**): one **`RuleBasedAIPlayer.decide`** per press for **`LegalActions.for_current_player`**, i.e. **whoever is current** — not an autopilot loop and **not** a per-seat “AI owns player 1” assignment.
- **Phase 5.2.1:** on **accepted** **`EndTurn`** (**`Space`** or AI-chosen **`end_turn`**), **[`EndTurnController.apply_hotseat_clear_after_accepted_end_turn`](../game/presentation/end_turn_controller.gd)** clears **unit** + **city** selection and **`CityViewState.reset_to_normal()`** (via **`city_production_panel.city_view_state`**) before the usual **HUD** refresh — so the next **current** player does not inherit the prior **City Hub** / **PLANNING** focus.
- **Phase 5.2.2:** **`PlayerContactStrip`** (**upper-right** **`HudCanvas`**) lists **`TurnState.players`** with **current-seat** highlight; **`TurnLabel.after_refresh`** (**`main.gd`**, **`_refresh_turn_hud_after_turn_label`**) refreshes **`TurnStatusPanel`** and **`PlayerContactStrip`** when the turn advances — **presentation-only**, no contact/diplomacy/fog.
- **Phase 5.2.5:** **`Unit`** MP — **`max_movement`** / **`remaining_movement`**; each accepted **`move_unit`** spends **1**; full refresh for a player’s units when that player **becomes** current (after **`end_turn`** + **`ProductionDelivery`** for the new actor, and once at session start for the opening current player). **`LegalActions`** / **`MovementRules`** respect exhausted MP.

**A2.10 automatic hand-fixture compilation (presentation-only):** the per-unit thumb surface evidence is no longer hand-authored. `hand_fixture_compiler.gd` (generic core) derives nail/pad patches, rest normals, rest-anchored winding, pad marker, bone-weight evidence and per-structure confidence from a rigged mesh plus an injected `family.bone_map(side)`, using skin-weight dominance, surface topology (connected components) and the hand's own dorsal/volar/radial directions — never albedo, brightness or saturation. Output is DATA: a versioned `hand_fixture_artifact.gd` resource carrying compiler version, schema, source-mesh SHA-256, family id, per-side patches and a deterministic content hash over the evidence the engine consumes. `compiled_hand_fixture.gd` adapts the artifact to the existing duck-typed fixture interface and rejects a stale, foreign, hand-edited or uncertified-side artifact by name. Pose calibration is a separate concern: `power_grip_1h_calibration.gd` owns the canonical thumb column and finger flexion as interaction-policy data, so the production path no longer reads the authored fixture at all. `uthana_a2_equipment_composition.gd` now injects the compiled artifact; `uthana_warrior_hand_fixture.gd` remains a development oracle and negative regression only. Stage is **CALIBRATING** — one reference rig, not batch-certified.

**A2.11 fixture identity, live-mesh binding and canonical ingestion (presentation + tooling):** an artifact is never accepted merely for being internally self-consistent. Three identity levels are separate and all enforced: **source mesh identity** (`source_mesh_sha256` vs an expected hash derived from the *asset* by `Compiler.mesh_identity_of_asset()`), **fixture semantic identity** (`content_hash` over the canonical payload), and **acceptance result** (bind sanity + the policy's ground-truth gate). Content identity is canonical rather than coarsely quantised: geometry is derived in skeleton space (`skinned_vertex_local`, `derive_frame(..., SPACE_SKELETON)`) with the whole skeleton pinned to rest for the compile, every float is snapped to `IDENTITY_QUANTUM = 1e-6` **as stored**, and the hash covers the entire payload except `content_hash` and the declared-provenance `source_asset` — so ancestor scale, scene placement and animation pose can no longer leak into identity, while a real geometric change still changes it. Live-mesh binding is mandatory: `CompiledHandFixture.from_artifact()` refuses an empty expected identity (`FIXTURE_MESH_IDENTITY_REQUIRED`) and `EquipmentAssembler.assemble()` calls `verify_against_mesh()` against the `MeshInstance3D` it is about to pose as its FIRST action, before any pose, socket or geometric bind sanity, with no fallback to the authored oracle or a generic default. The canonical automatic chain (import → family resolution → compile → artifact integrity → mesh binding → bind sanity → grip ground truth → machine-readable ACCEPTED/classified FAIL) is owned by `tools/assetgen/rig_ingest.py` (CLI `ingest-rig`, also called from the autorig download path) driving `presentation/equipment/tools/certify_hand_fixture_headless.gd` via `hand_fixture_ingest.py`; artifacts are written to staging and only an ACCEPTED chain publishes, and the exit protocol is `0` accepted / `2` classified asset-fixture FAIL with a named domain class / `1` infrastructure. Bone-name spelling is owned by the skeleton family (alias prefixes + `resolved_bone_map()`), not the compiler, so raw-Mixamo rigs resolve instead of being misreported as fingerless. `MIN_CLASSIFICATION_MARGIN` (0.08) moved out of the compiler into the versioned `hand_fixture_compiler_calibration.gd` and is injected, with its id/version inside the artifact hash. Compiler-PASS is not asset-ACCEPTED. Stage remains **CALIBRATING**; multi-unit batch certification has not started.

**A2.12 certified fixture trust boundary (presentation + tooling):** a compiler PASS is not a licence to run. **Height landmarks are semantic roles** (`head_top`, `foot_floor`) resolved by the injected skeleton family against the actual skeleton, so `skinned_mesh_geometry.gd`, `humanoid_hand_profile.gd` and `equipment_assembler.gd` contain no rig-name prefix of their own and both import representations of one humanoid measure the same height in a declared canonical space; a naming failure is `HUMANOID_HEIGHT_LANDMARKS_UNRESOLVED` while `DEGENERATE_HEIGHT` is reserved for genuinely flat geometry. **Identity is four levels, not three:** `source_geometry_sha256` (surfaces/vertices/indices/normals/UVs) and `source_rig_sha256` (skin bone indices, weights, bind matrices, bone names, parent hierarchy, every rest transform) replace the deformation-blind `source_mesh_sha256`, above `content_hash` and the new certification hash. **Acceptance has an owner:** `hand_fixture_certification.gd` — not the compiler — mints a `hand_fixture_certification_v1` envelope that embeds the evidence verbatim and binds the geometry/rig identities, family id + version, compiler/schema/calibration versions, policy id + version, acceptance schema + version, the completed eight-step chain and a digest of the acceptance report, all inside its own hash. The runtime loader accepts only that envelope, so staged evidence copied onto the published path is refused by resource type; publication is atomic (`os.replace` via a temporary file beside the destination) and a rejection never overwrites an accepted artifact. **Family version is verified** by the caller at load and assembly (`FIXTURE_FAMILY_MISMATCH`, `FIXTURE_FAMILY_VERSION_MISMATCH`; an empty expectation is a refusal), and **fixture verification is a declared contract** (`certified_runtime_v1` / `test_only_reference_v1`) rather than a `has_method` probe — `FIXTURE_BINDING_UNSUPPORTED`, `FIXTURE_VERIFICATION_REQUIRED`, `FIXTURE_NOT_CERTIFIED` — so the hand-authored A2.7 oracle can no longer assemble with `verified: false` and is reachable only behind an injected reference mode **and** `EOM_ALLOW_REFERENCE_FIXTURE=1`.

**A2.13a certification authority and independent acceptance evidence (presentation + tooling):** A2.12's own boundary was inverted, and its claim that the envelope proved a passed chain was wrong. `Certification.certify()` accepted the completed `chain` and the acceptance verdict **as caller parameters**, so `certify(evidence, {"chain": REQUIRED_CHAIN, "acceptance_report": {"pass": true}})` minted a certificate that verified, loaded through the production loader, assembled as `certified_bound` and survived save/load with **zero gates run**. The envelope proved integrity after minting, never execution. A2.13a moves the chain to the certification side: **`hand_fixture_certification_authority.gd`** is now the only public certification entry point, it takes real inputs only (asset path, staging path, hands, policy id, weapon), resolves the family and policy from its own registries, and itself imports, measures, compiles, re-reads, derives both source identities from the file, drives the real assembler and reads the achieved contact out of the real grip engine. `hand_fixture_certification.gd` builds the canonical acceptance report **as an output** of those observations — one entry per chain step carrying that step's own measurement — and `verify` re-derives the verdict from the entries, requires the recorded chain to be exactly `REQUIRED_CHAIN` in order, and requires the report's identities, family, policy and calibration to equal the envelope's, so a fabricated or borrowed report is refused even when correctly re-digested and re-hashed. `tools/certify_hand_fixture_headless.gd` is reduced to a CLI adapter with no way to assert a step. `bind_sanity` and `grip_ground_truth` are merged into one honest `assemble_and_measure` step (they were one measurement), so `ACCEPTANCE_SCHEMA` is `hand_fixture_acceptance_v2` and A2.12 certificates are refused rather than reinterpreted; the bind-sanity bootstrap envelope carries a distinct acceptance schema that `save()` refuses to write. **Certificate verification and runtime verification are documented as separate and both required** — the certificate is prior acceptance evidence, the live re-derivation against the actual mesh/rig plus the assembler's gates are the safety property — and the pose calibration and policy version the acceptance was measured under are now bound (`FIXTURE_CALIBRATION_MISMATCH`, `FIXTURE_CALIBRATION_VERSION_MISMATCH`, `FIXTURE_POLICY_MISMATCH`, `FIXTURE_POLICY_VERSION_MISMATCH`).

**A2.13b representation-invariant thumb surface (presentation + tooling):** the compiled thumb nail/pad was a property of the *delivery* rather than of the humanoid, and the cause was one operation. A2.13a decided each candidate triangle's outward sense by comparing its **skeleton-space** face cross product against the imported shading normal carried by `pose · rest⁻¹` — a carry that omits the bind pose and uses the basis where the **inverse-transpose** is required — so the two vectors compared lived in different frames and whether a triangle flipped depended on the export's bind representation. That is the whole 4 nail / 7 pad versus 4 / 10 result and the ~55° nail-plate difference; on the raw delivery **7 of 30** candidates flip under the superseded rule and none under the current one. Classification now happens in a declared canonical space (`thumb_distal_rest_local_v2`): positions are CPU-skinned vertices carried into the distal bone's own rest frame, directions are carried by each vertex's **inverse-transposed blended skin basis** with the reflection sign applied (`skinned_mesh_geometry.gd::skinned_normal_basis` / `skinned_normal_local`), and winding is resolved **once for the whole surface** by consensus between the geometric outward direction and the transformed imported normals — disagreement is `PATCH_WINDING_UNDERIVABLE`, never a silent geometry-only decision, and there is no per-triangle auto-flip. **The self-referential surface claims are reclassified, not deleted:** the bind-time and achieved-pose `|nail·pad − rest_nail_pad_dot|` checks measure *deformation drift* and never proved which surface was chosen, so they keep running as `thumb_surface_evidence_incoherent` / `thumb_surface_deformation_drift` / `thumb_surface_geom_deformation_drift`, and the anatomical question moves to **`thumb_surface_anatomy.gd`** — one implementation asked by both the compiler and the grip engine's patch bind, deriving every verdict from the resolved chain, this hand's chirality, the volar/radial frame, where each centroid sits off the digit's medial axis, the axial station from the distal joint in digit lengths, distal-segment weight dominance and patch non-overlap (`NAIL_PATCH_NOT_DORSAL_RADIAL`, `PAD_PATCH_NOT_VOLAR`, `NAIL_PAD_SAME_SIDE`, `NAIL_PAD_PATCH_OVERLAP`, `PATCH_NOT_DISTAL_STATION`, `PATCH_WEIGHT_BLEED_COMPONENT`, `PATCH_NORMAL_DISPERSED`, surfacing as `GRIP_SURFACE_ANATOMY_REJECTED`). Chirality is cross-checked rather than trusted: `hand_fixture_compiler.gd::frame_radial()` re-derives the radial sign from the frame's own thumb landmark and refuses a contradicting declared axis as `HAND_FRAME_RADIAL_INCONSISTENT`. Both deliveries of the reference humanoid now compile the same 4 nail / 10 pad plates and certify against **unchanged** thresholds, agreeing on every achieved gate metric to ~5·10⁻⁵; the R4 axial margin is ~1% on both, which is invariance evidence and not batch evidence. Compiler `hand_fixture_compiler_v4` / evidence `hand_fixture_evidence_v4`, so A2.13a evidence is refused rather than reinterpreted. The A2.8 hand-authored **left** reference fixture is refused by the new validation as anatomically wrong (its nail plate is on the dorsal-*ulnar* flank) — a finding, not a regression; left stays unsolved.

Presentation **reads domain** (**`scenario`**, **`game_state`**); authoritative rules stay **`try_apply`**.

Remaining 3D world integration per [PHASE_PLAN.md](PHASE_PLAN.md): N8c (production processing + spawn — **unblocked**; N8R review PASS at `709810c`), N8d (two-player loop checkpoint), followed by N9 full cutover + legacy removal — see also [WORLD_COORDINATES.md](WORLD_COORDINATES.md), [MAP_MODEL.md](MAP_MODEL.md).
- **Target production terrain pipeline:** generate the continuous 3D surface from the canonical 2D grid by running a **TS-08-equivalent solver** in Godot. Terrain solving and geometry generation are **Godot-only**; the server owns only the logical map — tiles, elevation, and derived edges — never solving or geometry. The mesh is a deterministic derivative — never gameplay authority.
- **TS-08 reference dataset (N2, 2026-08):** deterministic Stage-2 export at **`content/terrain/reference/handdrawn_test_map_full_01_ts08_stage2_reference_v1.json`** — a **derived reference golden** for parity testing and auditing the accepted TS-08 result. It does **not** replace the solver or become the final production terrain source. Exporter/audit: `tools/blender/terrain/export_ts08_reference_dataset.py`; schema and contract in **`content/terrain/reference/README.md`**. An optional N3 checkpoint that loads this file for early visual parity is temporary only — not target architecture.
- **Blender reference/tooling (development-only, outside the game):** the TS-08 chain under `tools/blender/terrain/` (see its `README.md` and `TERRAIN_PROTOTYPE_MANIFEST.md`). Never a runtime dependency; not a production terrain source. **Blender is also not a step in any asset-generation pipeline** (C1): it may be used to understand a format or prototype an approach, never to produce a pipeline artifact.
- **External asset providers (development-only tooling, outside the game — C1, 2026-08):** `tools/assetgen/` reaches image-generation, image-to-3D and character auto-rig providers. Nothing under `tools/` is imported by the Godot client or the authority server, and provider credentials (`MESHY_API_KEY`, `UTHANA_API_KEY`) are read from the environment by that package alone — never by the gameplay client. Provider-specific knowledge is confined to `tools/assetgen/providers/`; the job model, manifests and CLI speak neutral task types, so adapters are interchangeable. Jobs are idempotent (no double spend), resumable from a stored provider task id, and no command touches the network without `--live`. **Automated structural validation produces candidates, never approvals:** reports always carry `visual_status = PENDING_USER_REVIEW` and `production_approved = false`, and inferred equipment markers are diagnostics that never become runtime markers. Human review happens in `game/presentation/diagnostics/shield_inspection_diagnostic.tscn`, which implements no hand pose or grip solve. Full contract: [ASSET_PROVIDER_PIPELINE.md](ASSET_PROVIDER_PIPELINE.md).
- **Map content (implemented):** repo-root `content/maps/` with `reference/`, `authored/`, and `generated/` subdirectories ([MAP_CONTENT.md](MAP_CONTENT.md)). The TS-08 reference map is **`content/maps/reference/handdrawn_test_map_full_01.json`** (JSON envelope schema v1). Blender tooling loads it via `tools/blender/terrain/eom_map_content.py`. Godot consumes a **byte-identical derived copy** under `game/content/maps/` and the server consumes a second one under `server/content/maps/` (N5; packaged into the Docker image), both maintained by `python tools/content/sync_map_content.py sync` (per-destination `manifest.json`; dual-destination `check`). **`MapContentLoader`** (N1) reads the Godot package into **`WorldMap`**; `server/app/domain/map_content_loader.py` (N5) reads the server package into the Python `WorldMap`.

## Legacy map systems (frozen — removal planned N9)

The following **still exist in code today** but are **deprecated, frozen, and scheduled for removal**. New work must target **`WorldMap`**, not these systems. Breakage during the 3D migration is acceptable.

| Legacy component | Still exists? | Target disposition |
|------------------|---------------|-------------------|
| **`HexMap`** (GD + Python) | Yes | Remove N9; replaced by **`WorldMap`** (implemented N1 foundation) |
| Categorical `terrain` / `landform` / `woods` | Yes | Remove; physical properties + derived classifications |
| Category-based **`CityYields`** tables | Yes | Replace with yields v2 (planned N8) |
| Snapshot v2 cells `{terrain, landform, woods}` | Yes | Snapshot v3 + `MapIdentity` implemented (N6, opt-in `world_map` kind); v2 remains for legacy matches until retirement in N9 |
| 2D map renderer (`MapView`, `HexLayout`, overlays, fake-perspective camera) | Yes | Remove N9 |
| SubViewport 3D marker composite | Yes (opt-in experiment) | Replace with unified 3D world scene |

There is **no compatibility adapter** between legacy `HexMap` and the approved `WorldMap`. The existence of legacy code must not be mistaken for target architecture. Full policy: [MAP_MODEL.md](MAP_MODEL.md), [DECISION_LOG.md](DECISION_LOG.md) (2026-08-02 entries).

## Test architecture

- **Runner:** from repo root, [scripts/run-godot-tests.ps1](../scripts/run-godot-tests.ps1) runs a **fixed ordered list** of Godot headless scripts (**`-s res://…`**); count grows with new phases (see script array — includes **5.2.3** visibility tests, **5.2.4k** presentation gating tests, **5.2.4l** prototype sea-shell tests, **5.2.5** movement-points tests, **5.2.6** turn-start banner test, **5.2.6a** playtest display-name test).
- **Layout:** **`game/domain/tests/`**, **`game/presentation/tests/`**, **`game/ai/tests/`** — mix of invariant tests and tighter draw/UI harnesses; **`game/cloud/tests/`** (Slice C8) — snapshot adapter + HTTP URL/payload helpers (**no** live server in CI).
- **Asset-generation tooling (C1):** `python -m pytest tools/assetgen/tests -q`. Every HTTP response is a fake and the fake transport raises on any unprimed URL, so an accidental live provider call fails loudly instead of quietly costing money; real calls require `--live` and are never in a suite. `python scripts/scan-secrets.py` statically scans changed files for key-shaped content without echoing candidate values.
